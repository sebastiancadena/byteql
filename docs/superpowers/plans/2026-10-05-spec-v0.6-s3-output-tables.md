# Spec v0.6 Slice S3 (One `OutputTable` List) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `compileProjection` return one `outputs` list that defines every table a session
can emit (projected, flow, segments, `errors`), and route every consumer — session, schemas,
driver, and the query lint — through it, with `errors` built by `TableBatchBuilder`.

**Architecture:** The compiler computes `outputs` (order, column types, nullability) once,
taking the `errors` ordinal column as a compile option. The session builds one builder per
output and gains `appendIssue` to write `errors` rows; the driver still appends all issues at
EOF (streaming is S4). `projectionSchemas` becomes a projection of `outputs`, and
`byteql-pack build` lints queries against `outputs` plus the app-owned `_files`.

**Tech Stack:** TypeScript, apache-arrow, vitest, pnpm workspace; Node ESM for pack-tools.

**Spec:** `docs/superpowers/specs/2026-10-03-spec-v0.6-pack-boundary-design.md` — section D6, the
E6 evidence, "Migration plan" bar, and Sequencing row S3. S3 lands before S4 (streamed
`errors`), so `appendIssue` is the seam S4 will call at report time.

## Global Constraints

- Golden bar: every pack's `test/goldens/*.golden.json` and `schemas.snapshot.json` stay
  byte-identical. **Never run `vitest -u`.** A golden or snapshot diff fails the task.
- Output order is observable: spec tables in declaration order, then segments tables in
  first-use order, then `errors` — exactly today's `finish()` and schema order.
- `errors` column layout, in order: `error_id` int64, `stage` utf8, `<ordinal>` int32, `code`
  utf8, `message` utf8, `recoverable` bool, `_src_start` uint64, `_src_end` uint64; nullable:
  only `<ordinal>`, `_src_start`, `_src_end`. Default ordinal name `record`.
- The driver still emits a zero-row `errors` batch at EOF when nothing was reported, and still
  orders issues framer-first then engine (report order is S4).
- Each task ends green on `pnpm check && pnpm lint && pnpm -r test -- --run` from the repo root.
- Core `pnpm check` excludes `*.test.ts` from `tsc`; keep tests you touch type-correct anyway.
- Conventional commits; no `Co-Authored-By` trailers, no AI-branding text, no `/home/...` paths
  (a pre-commit hook rejects some of these words — never bypass it).
- Prettier via `pnpm format:check`; `rumdl fmt` on edited `.md` (MD013 warnings accepted).
- Branch: `feature/spec-v06-output-tables` (already created; the design-record rulings commit
  `2573d7a` is on it).

const ENGINE_NULLABLE = new Set(['stream_id', '_src_ranges']);

const projectedColumns = (table: CompiledProjectionTable): OutputColumn[] => {
  const declared = new Map(table.columns.map((column) => [column.name, column.nullable]));
  return Object.entries(tableOutputTypes(table)).map(([name, type]) => ({
    name,
    type,
    nullable:
